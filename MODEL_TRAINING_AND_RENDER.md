# PhishGuard: local model training and Render deployment

This version does **not** train models during Django/Gunicorn startup or on the
first URL request. It loads a pre-trained, versioned Joblib bundle into each
Render worker's RAM.

## 1. Python and dependency versions

Use Python **3.12.8** locally and on Render. The model artifact is serialized
with Joblib and must be loaded with the same pinned scikit-learn version used
for training. This project pins scikit-learn **1.5.1**.

The repository's `runtime.txt` and `render.yaml` both select Python 3.12.8.

## 2. Train once on your Windows machine

Open Command Prompt in the extracted repository root (the folder containing
`train_models.py` and `requirements.txt`). Activate your Python 3.12 virtual
environment, then run:

```bat
local312\Scripts\activate
python -m pip install --upgrade pip
python -m pip install -r requirements.txt
python train_models.py
```

If your virtual environment has a different name, activate that environment
instead. Training reads `detection_of_phishing_websites\Website_urls.csv`,
trains the five original classifiers plus the hard-voting ensemble, and writes:

```text
detection_of_phishing_websites\ml_artifacts\phishguard_model.joblib
```

The script prints the five holdout accuracy values. Training is intentionally
an explicit local command; it is not run automatically by Render.

## 3. Commit the trained artifact

After the training command succeeds, confirm that the `.joblib` file exists.
Then commit and push the source changes **and** the generated artifact:

```bat
git add .
git status
git commit -m "Load pre-trained PhishGuard models on startup"
git push
```

The artifact is deliberately not embedded in this source ZIP because it must
be generated with the exact pinned scikit-learn runtime. Do not commit `.env`
files, database URLs, passwords, or other secrets. The artifact contains the
trained model and vectorizer, not database credentials.

## 4. Render configuration

In the Render web service, retain/set these environment variables:

- `DATABASE_URL`: the Neon connection string from the `phish-guard-db` project.
  Use the Neon pooled endpoint if you are using the pooler. Do not put the URL
  in Git or share it publicly.
- `DEBUG=False`
- `SECRET_KEY`: a strong secret generated by Render or supplied securely.
- `ALLOWED_HOSTS`: include your Render hostname (the Blueprint default is
  `.onrender.com`).
- `ADMIN_USERNAME` and `ADMIN_PASSWORD`: set secure values.

The Render build command runs migrations and collects static files. The start
command uses one Gunicorn worker with four threads to avoid loading a separate
model copy into multiple worker processes. On startup, WSGI loads the committed
artifact into RAM. Restarts and wake-ups reload the artifact; they do not retrain.

If the artifact is missing or was built with a different scikit-learn version,
startup fails with a clear error rather than silently retraining or serving an
uninitialized model.

## 5. Updating the model in the future

When you want to refresh the model with a newer dataset:

1. Update and validate `Website_urls.csv` locally.
2. Run `python train_models.py` again in the pinned Python/dependency environment.
3. Review the printed holdout accuracies.
4. Commit and push the updated dataset and generated `.joblib` artifact.
5. Redeploy Render.

Do not train on every URL submitted. Prediction requests only transform the
submitted URL and run the already-loaded voting classifier.

## 6. Database safety

In local development (`DEBUG=True`), the app can use SQLite if `DATABASE_URL`
is not set. In production (`DEBUG=False`), `DATABASE_URL` is mandatory. This
prevents a missing Render variable from silently sending production writes to
an ephemeral SQLite file. Existing Neon data is not deleted or recreated by
these code changes.

## 7. Important model-artifact security note

Joblib uses Python pickle serialization. Only load the artifact generated by
your trusted local training process. Never accept or load an uploaded/untrusted
`.joblib` file. Keep Python and scikit-learn versions aligned between local
training and Render deployment.
